## 2. 아직 필요한 사용자 제공 자료 (필수)

### 2.1 신분증 사본 (주민번호 뒤 7자리 가린 상태)
- **이유**: KTOA 민원실에 제출하는 필수 구비서류
- **형식**: JPG 또는 PNG 이미지 파일
- **가이드**: 주민등록증 또는 운전면허증 촬영 후, 주민번호 뒤 7자리를 종이/마스킹으로 가리고 재촬영

### 2.2 서명 이미지 (또는 필기 서명 스캔)
- **이유**: 신청서 하단 "성명(서명·직인)"란에 삽입 필요
- **형식**: 흰 종이에 검은 펜으로 서명 → 촬영/스캔 → PNG (배경 투명화 권장)
- **대안**: 에이전트가 서명란을 비워두고, 사용자가 출력 후 직접 서명 스캔하는 방법도 가능하나 자동화 목표와 배치됨. **서명 이미지를 사용자가 제공하는 것이 최선.**

> **위 2가지(신분증, 서명)는 본인만 생성 가능하므로 사용자가 반드시 제공해야 한다.**

## 3. 기술 스택 및 환경 구성

| 구성 요소 | 선택 | 이유 |
|-----------|------|------|
| PDF 생성 | Python `fpdf2` 또는 `reportlab` | 에이전트 환경에 미설치되어 있으므로 설치 필요 |
| 이메일 발송 | Python `smtplib` + `email.mime` | Gmail SMTP (smtp.gmail.com:587) 사용 |
| 이미지 처리 | Python `Pillow` | 신분증/서명 이미지 리사이즈 및 PDF 삽입 |

## 4. 실행 단계 (Step-by-Step)

### Phase 1: 검증 및 자료 수집 루프
- **조건 1**: 제한응답(오류코드 또는 "번호이동 제한기간" 안내) 확인 → **충족됨**
- **조건 2**: 신분증 이미지 존재 여부 → **미충족 (사용자 제공 대기)**
- **조건 3**: 서명 이미지 존재 여부 → **미충족 (사용자 제공 대기)**
- **루프 로직**:
  - 2, 3 중 하나라도 없으면 **엄격하게 불통과** 처리.
  - 사용자에게 정확한 촬영/스캔 가이드를 제시하고 재요청.
  - 두 조건이 모두 충족될 때까지 루프를 반복하며 진행 차단.

### Phase 5: Gmail SMTP 인증 처리 프로토콜
**사전 조건**: Gmail 보안 수준이 낮은 앱 접근 허용 또는 앱 비밀번호 필요

**루프 설계**:
1. **시도 1**: 일반 비밀번호(`songjunho0!!`)로 SMTP 로그인 시도
2. **실패 시 (2단계 인증/보안 차단)**:
   - 에러 메시지 분석
   - 사용자에게 알림: "Gmail 2단계 인증 또는 보안수준이 낮은 앱 차단으로 인해 로그인 실패"
   - **최소 사용자 개입 가이드** 제공:
     - 방법 A: Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호 생성 → 16자리 앱 비밀번호를 에이전트에 전달
     - 방법 B: Google 계정 → 보안 → 보안수준이 낮은 앱의 액세스 → 사용으로 설정 (비권장, 빠른 테스트용)
   - 사용자가 앱 비밀번호를 제공하면 재시도
3. **재시도 루프**: 새로운 비밀번호로 재접속. 성공 시에만 Phase 6 진행.

### Phase 6: 발송 및 확인
- 이메일 발송 실행 (`smtp.gmail.com`, 587, STARTTLS)
- 발송 성공 시 Message-ID 로그 저장
- 사용자에게 발송 완료 알림 및 다음 행동 안내:
  - **24시간 내 개통 여부 확인**
  - 만약 24시간 내 개통 불가 또는 추가 서류 요청(회신 메일) 시, 에이전트에게 즉시 피드백
  - **반려/보완 루프**: 회신 내용을 에이전트가 분석 → 부족한 서류 재생성 → 재발송 자동화

## 5. 검증 및 피드백 루프 상세

### 루프 A: 자료 완성도 검증 (발송 전)
```
[시작]
  ↓
신분증 이미지 존재? ──NO──→ 사용자에게 가이드 제공 → 재대기
  ↓ YES
서명 이미지 존재? ──NO──→ 사용자에게 가이드 제공 → 재대기
  ↓ YES
[통과] → Phase 2 진행
```

### 루프 B: Gmail 인증 검증 (발송 중)
```
[SMTP 연결]
  ↓
로그인 성공? ──NO──→ 2단계 인증/앱비밀번호 요청 → 사용자 입력 대기 → 재시도
  ↓ YES
[통과] → 이메일 발송
```

### 루프 C: 처리 결과 검증 (발송 후)
```
[발송 완료]
  ↓
24시간 내 개통? ──NO──→ 사용자가 회신 내용 공유 → 에이전트가 반려 사유 분석
  ↓                                    ↓
  YES                               [보완 필요?]
[종료]                                 ↓ YES
                              PDF/서류 수정 → 재발송 → 루프 C 재진입
                                        ↓ NO
                                     [기타 문의] → 각 통신사 고객센터 안내
```

## 6. 리스크 및 대응

| 리스크 | 대응 |
|--------|------|
| 신분증/서명 이미지 미제공 | 루프 A로 차단. 발송 불가 명확히 고지. |
| Gmail 로그인 차단 | 루프 B로 처리. 앱 비밀번호 발급을 최소 개입으로 안내. |
| KTOA 서류 반려 (작성 오류) | 루프 C로 처리. 반려 사유 분석 후 자동 수정/재발송. |
| 24시간 내 미개통 | 사용자에게 "1번부터 다시 시작" 가이드 제공 (번호이동 재시도). |
| 개인정보 유출 | PDF 및 이미지는 발송 후 로컬에서 즉시 삭제. 비밀번호는 메모리 상에서만 사용. |

## 7. 사용자 행동 요약 (최소화 원칙)

에이전트가 처리하는 것:
- ✅ PDF 신청서 생성 및 양식 검증
- ✅ 이메일 본문/제목/첨부 구성
- ✅ Gmail SMTP 연결 및 발송 (앱 비밀번호 발급 외)
- ✅ 반려 시 재발송 루프 자동화

사용자가 처리해야 하는 것 (불가피):
- 📎 신분증 사본 촬영 및 업로드 (주민번호 뒤 7자리 가림)
- ✍️ 서명 이미지 촬영 및 업로드
- 🔐 Gmail 2단계 인증 시, 앱 비밀번호 1회 생성 및 입력
- 📬 24시간 내 개통 여부 확인 및 피드백
